## Summary

The candy installed the rootless binaries but carried none of the CONTAINERD.md §2/§4
checklist, promised rootless containerd/buildkit units that no `plan:` step wrote, and made
the nerdctl-full checksum advisory. Both halves of opencharly/layer-nerdctl#10 are closed
here, together with the checklist itself (opencharly/layer-nerdctl#11).

- **The helpers and the ranges.** `newuidmap`/`newgidmap` are declared per distro (`shadow`
  on Arch/Alpine, `uidmap` on Debian/Ubuntu, `shadow-utils` on Fedora), `containerd` is
  declared explicitly, and a plan step writes `user:100000:65536` to `/etc/subuid` and
  `/etc/subgid` for the uid-1000 user. The step resolves the name from the UID rather than
  hardcoding `user`.
- **The delegation and the user bus.** `/etc/systemd/system/user@.service.d/delegate.conf`
  carries `Delegate=cpu cpuset io memory pids`; `dbus`/`dbus-daemon`/`dbus-user-session` is
  installed for the `dbus.socket` the rootless unit requires.
- **The units.** The candy writes `~/.config/systemd/user/containerd.service` and
  `buildkit.service` from the upstream setuptool templates. `ExecStart` goes through
  `/usr/bin/env` so one unit serves both install prefixes (`/usr/local/bin` from
  nerdctl-full, `/usr/bin` from the distro packages), and the file carries a candy marker
  the checks assert.
- **The network driver.** The containerd unit pins
  `CONTAINERD_ROOTLESS_ROOTLESSKIT_NET=slirp4netns`. `pasta` and `bypass4netns` are
  documented from their measured state instead of being recommended, and
  `net.ipv4.ip_unprivileged_port_start` is a documented option, never forced.
- **The checksum.** The release publishes ONE `SHA256SUMS` file, not per-asset
  `.sha256sum` files, so the old `${url}.sha256sum` fetch 404'd and `|| true` hid it. One
  written verifier (no `--ignore-missing`, no `|| true`) now checks the archive against the
  extracted line, and a negative check proves a corrupted archive is rejected.
- **The CNI plugins at the declared path.** The nerdctl-full tarball extracts its CNI
  plugins to `/usr/local/libexec/cni`, but `nerdctl.toml` names `/opt/cni/bin`; a step links
  every real plugin at the ONE declared path, and a check asserts the five the conflist names
  resolve. (Arch's package already installs there; the tarball did not.)
- **The namespace.** `namespace = "default"` replaces the retired `charly` value in
  `nerdctl.toml`; the `charly` CNI network name stays (it names a network, not a containerd
  namespace).
- **The bed.** `check-nerdctl-rootless` is a disposable **Fedora** VM bed (the tarball arm — it
  proves the CNI-path fix end to end) whose candy is applied by the
  VM deploy's own `add_candy:` (not a nested `local:` member — see the filed plugin-check pin
  issue), in the three-step shape:
  ABSENCE (no rootless daemon, the system socket recorded), PERFORM (daemon-reload,
  linger, `containerd-rootless-setuptool.sh install` + `install-buildkit`), PRESENCE
  (`name=rootless` in `nerdctl info`, helpers resolve, `/dev/fuse` opens, units active,
  slirp4netns is the driver, a memory-limited container runs). PERFORM starts the
  candy-written units through systemd and waits for `nerdctl info` before running the
  setuptool: the installer gives a unit three seconds, which a cold guest can exceed, and a
  slow start must report the unit's journal rather than an opaque exit. The daemon-safety proof
  asserts the daemon's namespace socket is the USER socket by device:inode across
  `/proc/<pid>/root`, that the host system socket is a different object or absent, and
  that its inode/mtime is unchanged before/after.
- **The bed image declares its distro chain.** Without `distro: ["fedora:43", fedora]`
  `img.DistroDef` is nil and the generator emits no declarative package installs, so the
  candy's package arms did nothing. The first run's `command -v dbus-daemon` failure is
  how that surfaced.
- `/image/` is ignored: the VM bed renders a disk + seed there.
