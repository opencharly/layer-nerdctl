### Why the candy-relative path, and why this leg matters beyond itself

`sdk/deploykit/skills_collect.go` resolves the tree as:

```go
base := layer.GetSourceDir()
sf, err := candywalk.ReadSkillFile(filepath.Join(base, skillTree), name)   // skillTree = ".agents/skills"
```

`GetSourceDir()` is the **candy's** directory, and `spec.CandyModel` carries no `Skills` field — so a project
cannot declare its way to a repo-root tree. The loader reads `<candy dir>/.agents/skills/<name>/SKILL.md` and
nothing else.

This leg started at the repository root, like the repos the original baseline called "fully migrated", and the
build refused it:

```
charly: error: command "build": render-prep check-nerdctl-app: skill "layer-nerdctl":
no body — the node carries no in-line content: and no SKILL.md exists under .agents/skills
beside the owning candy "layer-nerdctl"
```

Moving the file to the candy-relative path, with no other change, makes it pass.
